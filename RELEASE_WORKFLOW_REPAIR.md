# Flowly release workflow repair

This repair hardens `.github/workflows/release.yml`:

- Accepts tags with lowercase or uppercase `v` prefix, and plain version tags.
- Requires `MAJOR.MINOR.PATCH` format.
- Calculates `versionCode` from the release tag and rejects releases at/below the 1.1.0 baseline.
- Verifies the generated release APK's internal `versionName` and `versionCode` match the tag before publishing.
- Keeps the existing signing, SHA-256, and GitHub Release asset steps.

## Publish the next build

1. Upload/merge these repaired files to your repository's default branch.
2. Do not reuse a tag that already exists. Choose the next unused version tag, e.g. `v1.2.1` if `v1.2.0` has already been published.
3. Confirm GitHub Actions runs **Release Flowly APK** from the new tag and completes successfully.
4. Use the APK and `.sha256` file generated by that workflow—not a debug APK artifact.
5. The signing keystore/secrets must remain the same as the key used to sign the installed app.

The APK version metadata validation is included to fail the workflow early if a tag and APK version disagree.
